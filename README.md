# Dashboard metrology

Planned Django module and scheduled OMERO metrology processor for the [CCI dashboard](https://github.com/CCI-GU-Sweden/Dashboard-django), using [METEOR-core](https://github.com/CCI-GU-Sweden/METEOR-core). The existing METEOR-view Flask application is the reference for processing, scoring and UI behavior.

The microscope page offers lens and category score histories, followed by measurement charts and matching analysis figures. The filterable measurements table is available from the metrology overview; the score table is optional on the microscope page. Figures are served to staff from processor-saved, linked PostgreSQL artifacts, matched to the image and analysis-result index; arbitrary OMERO attachments are not fetched. The history is limited to the latest 5,000 dated measurements, and the figure gallery to 36 figures per selection.

The `dashboard_metrology` Django module provides a staff-only microscope and measurement viewer, interactive measurement and score history, and an unresolved-fileset review page. The history uses the most recent 5,000 dated measurements for the selected microscope/lens, separates different units, and labels import-time fallback. Scores are computed on demand from current database measurements and thresholds; administrators can queue a whole fileset for REDO. The separate processor and PostgreSQL schema have been exercised against test OMERO. A daily 16:00 Europe/Berlin CronJob is enabled in `core-omero-test`. Crash recovery and production deployment still require further work. See [Installation.md](Installation.md) for setup, [Proposal.md](Proposal.md) for the design, and [Discovery.md](Discovery.md) for findings.

Scoring follows METEOR-view's grace curve: a value within the threshold range scores 1; outside it the score falls quadratically to 0 over three times the distance between the expected value and the applicable bound. The latest configured threshold for a lens magnification, NA, category, metric and unit is used. Legacy thresholds without a unit are used only when that metric has one unit. Otherwise a provisional range is calculated from the current median of at least three completed measurements of the same lens type, category, metric and unit, with bounds ±10% of the median magnitude. Missing thresholds or too few samples leave a measurement unscored. Ignored and failed measurements are excluded. Per day, category scores are the median of measurement scores, lens scores the mean of categories, and microscope scores the mean of lenses. Aggregate status is success at ≥0.7, warning at ≥0.4, and critical below 0.4. Acquisition timestamps fall back to import time. Scores are not persisted in `metrology_score`: they and the derived reference can change as new data arrives. This differs from METEOR-view's initially derived thresholds, which it stores; configure a threshold to keep the reference fixed. No scores are silently calculated from missing calibration.

Microscope drawings are adapted from METEOR-view; see [METEOR_VIEW_LICENSE](METEOR_VIEW_LICENSE).

Run `python scripts/update_test_meteor_core.py` to build the current METEOR-core `main` and update the test CronJob to its immutable image digest without contacting OMERO. Updates are on demand, not automatic.

Administrators can queue REDO from the Measurements table. The next daily processor prioritizes queued filesets within its ten-fileset limit. At most one active request per fileset is allowed. Existing results remain active until the replacement completes and its attachments are linked; older results and attachments are retained. A request is retried up to three times, with status and errors in the REDO queue. Missing or inaccessible filesets remain pending for investigation. Scores and all dashboard views use the latest successfully completed generation.

Staff can review thresholds; administrators can save a new version for each observed measurement and lens type. Each version records the author, and bounds must be finite with lower ≤ expected ≤ upper. Changes apply to scores on the next request. On the attention page admins can queue a failed fileset without a successful measurement. Future failed runs retain their OMERO image IDs for direct links.

Administrators may ignore an individual measurement after two confirmations. Its status change and previous status are audited; ignored measurements are excluded from graphs and scoring, and the current ignore state is preserved for the same metric when a fileset is reprocessed. The Measurements page offers Restore to recover the previous status from the audit history. Category score details show the corresponding per-image figure and offer fileset REDO and measurement ignore actions.

Microscope cards show an additional Overdue badge when the most recent non-ignored measurement is older than one calendar month in Europe/Stockholm. Acquisition time is used where available, otherwise OMERO import time; microscopes without a dated measurement are not counted as overdue. The dashboard overview reports the total number overdue.
